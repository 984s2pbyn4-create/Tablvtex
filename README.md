# ТекстФорма v1.0

Автономное веб-приложение для преобразования Excel в текст по настраиваемым правилам и для экспорта готового документа в TXT или DOCX. Интерфейс на русском языке. Работает непосредственно в Safari на iPad, без серверной обработки и без внешних библиотек.

## Развёртывание на GitHub Pages с iPad

1. Скачайте архив `ТекстФорма_GitHub_Pages_v1.0.zip` и откройте его в приложении **«Файлы»**. Коснитесь архива, чтобы распаковать его.
2. Создайте **публичный** репозиторий на GitHub или откройте существующий репозиторий. Приложение не требует GitHub Actions.
3. Откройте сайт GitHub в Safari. В репозитории выберите **Add file → Upload files** и загрузите **содержимое распакованной папки** (все файлы, не сам ZIP), в корень ветки `main`. Все файлы лежат в одном уровне, создавать папки не нужно. Обязательно загрузите `index.html`, `app.js`, `engine.js`, `excel.js`, `zip.js`, `docx.js`, `db.js`, `worker.js`, `styles.css`, `sw.js`, `manifest.webmanifest` и изображения иконок.
4. В настройках репозитория откройте **Settings → Pages → Build and deployment**. Выберите **Deploy from a branch**, ветку **main** и папку **/(root)**, затем сохраните.
5. Откройте опубликованный адрес GitHub Pages в Safari. Обычно это `https://<имя-аккаунта>.github.io/<имя-репозитория>/`.
6. В первый раз откройте сайт **при наличии интернета**, дождитесь статуса **«Автономный режим готов»**. В Safari нажмите **Поделиться → На экран «Домой»** и добавьте приложение.
7. Запустите его **с экрана «Домой» при наличии интернета** ещё раз, дождитесь статуса готовности автономного режима, затем проверьте в авиарежиме. После этого интернет не требуется для открытия приложения, импорта локальных таблиц, конвертации и экспорта файлов.

Важно: GitHub Pages разворачивается из отдельных файлов, а не из ZIP-архива. На iPad при необходимости выбирайте файлы для загрузки несколькими партиями, но в одной и той же корневой папке репозитория.

## Как работать

1. **Источник данных:** выберите XLSX, XLSM, CSV или TSV, лист и строку заголовков.
2. **Сопоставление:** свяжите произвольные столбцы с ролями `groupKey`, `locality`, `comment`, `square`, `targetId`, `targetType`.
3. **Фильтры:** настройте условия отбора по любым столбцам, если требуется.
4. **Группы и порядок:** выберите сортировку, пользовательский заголовок и текстовые префиксы. Для ручного порядка используйте стрелки вверх и вниз.
5. **Ветки и маски:** включайте/выключайте ветки, редактируйте маски, разделители, служебный префикс и порядок элементов.
6. **Документ:** проверьте результат в правой панели. Вкладка «Ручная правка» позволяет изменить текст без вмешательства в исходную таблицу.
7. **Экспорт:** скачайте TXT или DOCX. Сохраняйте и переносите шаблоны через JSON.

Таблица при обычном импорте используется только во время работы приложения. Если включить «Хранить загруженную таблицу на устройстве», импортированная таблица сохраняется в IndexedDB браузера и может автоматически восстановиться при повторном открытии.

## Поддерживаемая логика

- Группировка по `groupKey`; отдельный абзац на группу.
- Ветка А: пустой комментарий; подгруппы по `locality`; уникальные квадраты и номера.
- Ветка Б: заполненный комментарий; удаление заданного начального префикса; подгруппы по очищенному комментарию и квадрату; без вывода населённого пункта.
- Номера выводятся после населённого пункта или комментария; разделение через запятую без повторений.
- Пустые ветки автоматически пропускаются.
- Условия отбора, последовательность групп и веток, маски и текстовые префиксы определяются пользователем.
- Настраиваемый общий и индивидуальный заголовок группы.
- Сохранение / загрузка пользовательских шаблонов в JSON и в локальной библиотеке.
- Предпросмотр и предупреждения о пустотах и конфликтах.

## Поддерживаемые форматы и ограничения

- **Вход:** `.xlsx`, `.xlsm`, `.csv`, `.tsv`; максимальный размер загружаемого файла 35 МБ. Старый бинарный `.xls` и защищённые паролем книги не поддерживаются: сохраните их как `.xlsx`/CSV.
- **Выход:** редактируемый `.docx` и `.txt` с UTF-8 BOM; пользовательские настройки в `.json`.
- **Макросы XLSM не запускаются.** Чтение ориентируется на значения ячеек, кэшированные результаты формул и стандартные строковые данные OOXML. Сложные пользовательские числовые форматы, даты и формулы, не имеющие сохранённого результата, могут требовать проверки пользователем. Простейшие форматы вида `0000` сохраняются при чтении числовых идентификаторов.
- **Без интернета:** доступно после успешной установки PWA-кеша в Safari. Приложение не загружает данные в облако. Операционная система может очищать данные сайтов при нехватке памяти, поэтому делайте резервные копии JSON и готовых документов в «Файлы».
- **Совместимость:** современные версии iPadOS Safari с поддержкой Service Workers, IndexedDB и `DecompressionStream('deflate-raw')` (iOS/iPadOS 16.4+). Для старого Safari потребуется обновление ОС.
- **Разделение хранилищ:** Safari и приложение на домашнем экране iPad могут использовать раздельные локальные хранилища. После установки в PWA импортируйте нужный JSON-шаблон ещё раз, если он не появился автоматически.
- При ручной правке исходный Excel не меняется. Повторная генерация по правилам может заменить исправленный текст только после подтверждения.

## Архитектура

- `index.html` и `styles.css` — адаптивный пользовательский интерфейс.
- `app.js` — состояние, формы, настройки, импорт, предпросмотр и экспорт.
- `excel.js` — локальное чтение XLSX/XLSM/CSV/TSV.
- `zip.js` — распаковка ZIP/OOXML и создание архива для DOCX.
- `engine.js` — независимый детерминированный движок фильтрации, группировки, сортировки, уникальности и текстовых масок.
- `worker.js` — обработка крупных таблиц вне интерфейсного потока.
- `docx.js` — генерация редактируемого OOXML DOCX.
- `db.js` — сохранение шаблонов и при желании таблицы через IndexedDB.
- `sw.js`, `manifest.webmanifest` и иконки — автономный режим и установка на домашний экран.

Ни один файл не обращается к CDN, стороннему API или серверу для обработки пользовательских таблиц.

## Обновления и резервные копии

Для обновления замените файлы приложения в GitHub на новые. При релизе новой версии должна меняться строка `CACHE` в `sw.js`, чтобы установленная PWA получила новые файлы при подключении к сети. Перед крупными обновлениями экспортируйте JSON-шаблоны.

## Проверка работоспособности

Если есть Node.js: `node tests/run-tests.js` (тесты находятся в исходной папке разработки, в релизном архиве они не требуются). Для обычного развёртывания на GitHub Pages установка Node.js и сборка проекта **не нужны**.
